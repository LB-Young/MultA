## 一、项目背景与目标

### 1.1 背景：从“信息孤岛”到“智慧神经”
当前企业面临的核心问题已从“数据存储”转向“大模型调用”。传统文件管理方式（Wiki、网盘、共享文件夹）导致知识沉睡、检索低效，大量非结构化数据（如PDF、图纸、工艺卡片、合同）无法被AI直接理解，形成“数据孤岛”。基于RAG（检索增强生成）技术的企业知识库，能将静态文档转化为具备逻辑推理能力的智能体，实现知识的“瞬时唤醒”与“主动交付”。

### 1.2 建设目标
- **短期目标：** 基于现有硬件资源（用户确认拥有24GB显存的NVIDIA 4090显卡），搭建私有化RAG知识库系统，实现企业文档的智能问答与检索。
- **中期目标：** 支持多轮迭代检索（智能RAG/Agentic RAG），解决“关键词失配”和“信息不完整”问题，答案准确率提升至90%以上。
- **长期目标：** 沉淀隐性知识（如专家经验、故障处理诀窍），构建工艺知识图谱，实现知识的数字化传承。

## 二、RAG技术原理与选型建议

### 2.1 RAG核心流程
RAG通过“检索-增强-生成”三层逻辑工作：
1. **离线处理（知识库构建）**：将企业文档切片、向量化，存入向量数据库。
2. **在线检索**：用户提问时，将问题向量化，在库中检索最相关的Top-K片段。
3. **增强生成**：将检索到的片段作为上下文，与大模型结合生成答案，并附上来源。

### 2.2 2026年技术趋势：从“静态RAG”到“智能RAG”
传统静态RAG采用单向线性逻辑（提问→检索→生成），若首次检索未命中则流程中断。智能RAG（Agentic RAG）引入**反思与迭代机制**：
- 意图拆解与关键词转换（如“博士”→“学历构成”→“员工总数”）
- 多轮检索与结果自审
- 链式追溯（如发现“详见附注X”，自动追加检索附注内容）

### 2.3 基于4090 24GB硬件的选型建议
结合用户此前讨论的硬件条件（24GB显存、130MB模型规模），推荐以下部署方案：

| 组件 | 推荐选型 | 理由 |
| :--- | :--- | :--- |
| **基础模型** | Qwen2.5-7B-Instruct（4-bit量化） | 7B模型4-bit量化后约3.5-4GB显存，24GB可轻松运行，且支持长上下文 |
| **嵌入模型** | BAAI/bge-large-zh-v1.5（1.5B参数，FP16） | 中文语义理解优异，显存占用约3GB |
| **重排序模型** | BAAI/bge-reranker-large | 提升Top-K结果的精度，显存占用约1.5GB（可选） |
| **向量数据库** | Milvus或Qdrant（本地部署） | 开源、高性能，支持混合检索 |
| **RAG框架** | Dify社区版 或 FastGPT | 可视化编排、工作流支持、多智能体协同 |
| **部署方式** | Docker Compose（私有化） | 数据完全内网控制，满足安全合规要求 |

## 三、技术建设方案

### 3.1 数据层：知识预处理与向量化
智能体的表现70%取决于数据处理。需建立标准化的ETL（提取-转换-加载）流程：

1. **多源数据接入**：支持PDF、Word、Excel、PPT、CAD图纸、图片（OCR）、音视频转写等。
2. **智能分块（Chunking）**：
   - 策略：基于语义边界切分（如按章节、段落），设置重叠窗口（overlap）保障上下文连贯。
   - 推荐块大小：500-800字（或300-500 tokens），可调优。
3. **元数据标注**：为每个块添加文档来源、版本、部门、标签等信息，提升检索精度。
4. **向量化**：使用嵌入模型（如bge-large-zh）将文本块转为高维向量，存入向量数据库。
5. **知识图谱增强（可选）**：对结构化信息（如“产品-部件-工艺-专家”）构建实体关联，支持推理式问答。

### 3.2 检索层：混合检索与重排序
单一向量检索可能遗漏关键词匹配，推荐采用**混合检索**策略：
- **向量检索**：召回语义相似内容（HNSW算法，毫秒级响应）。
- **全文检索**：基于关键词（如产品型号、合同编号）精准匹配。
- **重排序**：使用交叉编码器（Cross-Encoder）对Top-K结果精排，剔除噪声。
- **效果指标**：混合检索+重排序可使召回率达92%以上。

### 3.3 生成层：提示词工程与智能RAG工作流
在RAG框架中编排智能体流程，核心指令示例（参考MaxKB的Agentic Workflow）：

```markdown
## 角色设定
你是企业知识库智能助手，严格依据检索到的文档内容回答问题。

## 深度检索逻辑（多轮迭代）
1. 关键词转换：将用户口语转化为标准术语（如“去年赚了多少”→“营业收入、净利润”）。
2. 多轮检索：若首轮未命中，自动切换同义词、近义词、所属大类进行二、三轮检索。
3. 链式追溯：若结果提示“详见附注X/附录Y”，必须追加检索该部分内容。
4. 结果自审：生成前检查信息是否完整，若缺失则继续检索。

## 回答规范
- 必须附上来源（文档名+页码/章节）。
- 若知识库中无相关内容，引导用户联系人工，严禁编造。
- 结构化呈现（表格、列表）优先。
```

### 3.4 应用层：多终端与业务系统集成
- **交互方式**：Web端对话、企业微信/飞书机器人、API接口。
- **业务集成**：通过API对接CRM、ERP、PLM等系统，实现“知识即业务”闭环。

## 四、部署与安全

### 4.1 私有化部署架构
基于用户4090 24GB显卡，采用Docker Compose部署方案：
- **应用服务**：Dify/FastGPT（CPU+内存）
- **向量数据库**：Qdrant/Milvus（CPU+内存）
- **大模型服务**：Ollama/vLLM加载Qwen2.5-7B（4-bit）（GPU 4GB）
- **嵌入模型**：bge-large-zh（GPU 3GB）
- **重排序模型**：bge-reranker-large（GPU 1.5GB，可选）
- **总显存占用**：约8-9GB，剩余显存可供高并发查询或更大batch使用。

### 4.2 安全与权限管控
企业级知识库需构建“身份认证-权限控制-操作审计”三重体系：
1. **身份认证**：集成LDAP/AD域，支持MFA。
2. **细颗粒度权限**：支持文档级、段落级、字段级权限控制，确保不同角色只能访问授权内容。
3. **操作审计**：记录所有检索、问答、导出日志，满足等保合规要求。

### 4.3 信创适配（可选）
如需国产化环境，可适配鲲鹏/飞腾CPU、麒麟OS、达梦数据库等信创生态。

## 五、运营优化与持续调优

### 5.1 RAG调优技巧
- **分块大小调优**：根据文档类型调整（长文档用800字，技术手册用300字）。
- **检索Top-K调优**：通常K=3~5，结合重排序可适当增加K值。
- **提示词迭代**：根据用户反馈持续优化Prompt。

### 5.2 知识库日常运营
- **标准化目录**：按部门/业务/文档类型建立三级分类。
- **增量更新**：新增文档自动触发向量化与入库。
- **质量评估**：建立人工反馈机制，定期评估问答准确率，优化切片与检索策略。

### 5.3 性能优化（高并发/大知识库）
- **缓存策略**：Redis缓存高频问题与检索结果。
- **异步处理**：大文件导入、向量化采用消息队列（如NATS）异步执行。
- **冷热分离**：历史归档数据与高频访问数据分离存储。
